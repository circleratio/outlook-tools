# 概要
MS365 のスケジューラ（予定表）から、指定期間の空き時間を取得するツール。
抽出した空き時間を標準出力に出すと同時に、クリップボードにコピーする。
主な用途は、日程調整メールへの返信に貼り付ける空き時間候補の作成。

フロントエンドは 2 つあり、空き時間の抽出ロジック（`src/OpenSlot`）を共有する。

| 版 | 実体 | カレンダー取得手段 | 主な利用者 |
|---|---|---|---|
| Graph 版 | `openslot.ps1`（CLI） | Microsoft Graph PowerShell SDK（`Connect-MgGraph`・対話サインイン） | 端末で直接コマンドを叩く |
| MCP 版 | Claude Code スキル `openslot` + `openslot-mcp.ps1` | Claude の Microsoft 365 コネクタ（`outlook_calendar_search`） | Claude Code 上でメール返信中に呼ぶ |

以下の「要求仕様」「空き時間の抽出ルール」「出力」「出力フォーマット」は両版で共通。
版ごとの差分は「## 版ごとの仕様」に記す。

# 要求仕様

## 対象・入力
- 対象期間は開始日と終了日を引数で指定する（両端を含む）。例: `-Start 2026-09-01 -End 2026-09-05`。
- 日付は `yyyy-MM-dd` 形式のほか、年を省略した `MM-DD` 形式でも指定できる。年を省略した場合はコマンド実行年（今年）を補う。
- 開始日（`-Start`）を省略した場合は、コマンド実行日の翌日を開始日とする。
- 終了日（`-End`）を省略した場合は、開始日の「次の金曜日」を終了日とする。
  - 開始日が月〜木なら同じ週の金曜日。
  - 開始日が金曜日、または土日にコマンドを実行して開始日が土日になる場合は、翌週の金曜日。
- 既定値を適用した結果、終了日が開始日より前になる場合は、対象日なしとして正常終了する（exit 0、標準出力・クリップボードは空）。
- `-Start` と `-End` の両方を明示指定していて終了日が開始日より前の場合は、引数エラー（exit 1）。
- `-Week <数字>` を指定すると、対象期間を「`<数字>` 週後の月曜日から、`<数字>` 週後の金曜日まで」とする。
  - 基準はコマンド実行日を含む週（月曜起算）。その週の月曜日に `<数字>×7` 日を加えた日を開始日、その 4 日後（金曜日）を終了日とする。
  - ただし `-Week 0`（今週）のときだけ、開始日はその週の月曜日ではなく「コマンド実行日の翌日」とする。終了日は今週の金曜日のまま。
    - この結果、金曜以降に `-Week 0` を実行すると開始日が終了日より後になる。その週は対象日なしとして扱う（出力しない）。
  - `<数字>` は 0 以上の整数。負数はエラー（exit 1）。
  - `-Week 0,2,4` のようにカンマ区切りで複数の週を指定できる。重複は除き、週の昇順で各週の期間を順に出力する。
  - `-Week` は `-Start` / `-End` と同時に指定できない。同時指定はエラー（exit 1）。
- MS365 へのアクセスは、コマンドを実行したユーザーの権限（委任認証）で動作する。カレンダー取得手段は版ごとに異なる（「## 版ごとの仕様」）。
- 技術スタックは PowerShell。動作環境は Windows 限定でよい。

## 空き時間の抽出ルール
- 予定表で予定が入っていない時間帯を空き時間として抽出する。
- 「予定が入っている」と見なす表示区分（showAs）は `busy` / `oof`（外出中）/ `tentative`（仮の予定）。`free` と予定なしのみを空きとする。
- 除外する時間帯（毎営業日）:
  - 早朝: 8:00 より前
  - 昼休み: 12:00〜13:00
  - 夜: 19:00 以降
  - → 実質の対象時間帯は平日 8:00〜12:00 および 13:00〜19:00。
- 土日は対象から除外する。
- 祝日は現在の実装では検索対象に含める。将来的にオプションで除外を選べるようにする。
- 空き枠は 30 分刻みに丸める。予定境界を含む 30 分スロットは空きとしない。
- 出力する空き枠の最小サイズは既定で 30 分。`-Duration <分>` で変更できる。
  - `<分>` は 30 の倍数（30 以上）。それ以外はエラー（exit 1）。
  - 例: `-Duration 60` なら 60 分以上まとまって空いている枠だけを出力する。
- タイムゾーンは JST 固定で計算する。

## 出力
- 抽出結果を標準出力へ出す。
- 標準出力と同一の全文をクリップボードにコピーする。
- 指定期間内で空き時間が全く無い営業日は、行を出力しない。

# 出力フォーマット
- 日付は 0 埋めしない。
- 曜日は日本語表記。
- 1 営業日につき 1 行。空き時間帯をカンマ区切りで並べる。

```
M月d日(wday): h1:m1-h2:m2, h3:m3-h4:m4, ...
```

# 使いかた

```powershell
# 2026-09-01 から 2026-09-05 の空き時間を取得
.\openslot.ps1 -Start 2026-09-01 -End 2026-09-05

# 開始日を省略 … 実行日の翌日から、その週（開始日の週）の金曜日まで
.\openslot.ps1

# 終了日のみ省略 … 指定した開始日から、その次の金曜日まで
.\openslot.ps1 -Start 2026-09-01

# 年を省略（MM-DD）… 実行年を補う
.\openslot.ps1 -Start 09-01 -End 09-05

# 2 週後の月曜日〜金曜日
.\openslot.ps1 -Week 2

# 今週（翌日〜金曜）・翌週・3 週後をまとめて
.\openslot.ps1 -Week 0,1,3

# 60 分以上まとまって空いている枠だけ
.\openslot.ps1 -Week 1 -Duration 60
```

出力例:

```
9月1日(火): 8:00-10:00, 13:00-15:30, 17:00-19:00
9月2日(水): 8:00-12:00, 13:00-19:00
9月4日(金): 9:00-12:00
```

（同じ内容がクリップボードにもコピーされる）

# 版ごとの仕様

## Graph 版（`openslot.ps1`）

- 上記「使いかた」がそのまま該当する。
- カレンダー取得は Microsoft Graph PowerShell SDK（`Connect-MgGraph -Scopes Calendars.Read`、
  対話サインイン）。`Microsoft.Graph.Authentication` モジュールが前提。
- 終了コード: 0=正常 / 1=引数不正 / 2=認証失敗 / 3=カレンダー取得失敗。

## MCP 版（Claude Code スキル `openslot`）

- 目的は、Claude Code 上で日程調整メールに返信する際に、空き時間候補を素早く得ること。
- スコープは **空き時間の抽出まで**。抽出結果を標準出力に出し、クリップボードにコピーする。
  返信メール本文への反映は、スキルの結果を見てユーザーが都度 Claude に指示する（スキルの責務外）。
- 対象期間の指定方法は Graph 版の CLI 引数体系を踏襲する（`-Start` / `-End` / `-Week` / `-Duration` /
  `-NoClipboard` と同じ意味・同じ既定値・同じ検証）。自然言語での期間指定は Claude が
  この引数体系へ変換してからスキルを起動する。
- カレンダー取得は Claude の Microsoft 365 コネクタの `outlook_calendar_search` を用いる。
  - 認証は Claude 側で確立済みのコネクタ接続を再利用する（スキル実行時にサインインを求めない）。
  - `outlook_calendar_search` は 1 応答あたり最大 25 件。`nextOffset` を辿って対象期間の全件を取得する。
  - 応答の `showAs` / `isAllDay` / `isCancelled` と、`start` / `end` の
    `{ dateTime, timeZone }` を用いる。`timeZone` は原則 `Tokyo Standard Time`。
  - 「予定あり」と見なす条件は Graph 版と同一（`showAs` が `busy` / `oof` / `tentative`）。
    `isCancelled = true` の予定は除外する。`free` / `workingElsewhere` は空きとして扱う。
- 空き算出・整形・既定期間の解決・出力フォーマット・終了コードの意味は Graph 版と共通
  （抽出ロジック `src/OpenSlot` を共有する）。ただし MCP 版に認証失敗コード（Graph 版の 2）は無い。
- 動作環境は「Claude Code + Microsoft 365 コネクタ接続済み」。Windows（`Set-Clipboard` を使う）。
- `Microsoft.Graph` モジュールへの依存は無い。
